# Программа владеет входом и обновлением CI-сессии

8 октября 2026 года пользователь закрепил внешний auth lifecycle: программа установки сама обновляет и надёжно публикует отдельную CI-сессию, затем передаёт официальному App Server 0.160.1 только access token через `chatgptAuthTokens`. Refresh token остаётся у программы; runtime и Node pins сохраняются, собственная сборка Codex не нужна. Решение заменяет managed refresh внутри App Server из 07/13: на stock binary воспроизведена потеря новых tokens при file-save failure с успешным account response, а external-token read/selected-ID consume работают на synthetic стенде.

Протокол Repository Secret + durable intent → target → Secret PUT → finalize сохраняется; публикация обновлённой сессии завершается до выдачи access token runtime. При external refresh request текущий интервал останавливается, обслуживание выполняется отдельно; неизвестный consume не повторяется. Первый/повторный вход после отзыва требует пользователя. External API experimental: положительный клиентский lifecycle реализует [host lifecycle](../auth-storage.md), GitHub интеграцию — 17, установку — 18, реальные OAuth/серверные свойства — 21. Решение не означает готовность живого запуска.
