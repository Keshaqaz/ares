# Две площадки воркера: GitHub и Google Apps Script

20–21 октября 2026 года проба (`.scratch/apps-script-worker/issues/01-deploy-probe.md`) показала, что воркер можно развернуть из CLI в Google Apps Script в аккаунте пользователя. Триггер `everyMinutes(1)` за 15 минут не пропустил ни одного тика, тогда как GitHub доставляет около 23% слотов. Цена Apps Script — два экрана «непроверенное приложение», ручной переключатель `usersettings` и проект, который CLI не может удалить. Поэтому Apps Script добавлен **рядом** с GitHub, а не вместо него.

**Решение.**
- Площадки равноправны. `setup` спрашивает площадку без рекомендации, на экране воркера в CLI её можно сменить.
- **Активный воркер не больше одного.** Два воркера с одной квотой могли бы применить два сброса на одно исчерпание: проверка «окно уже восстановлено» у каждого своя. На паузе активного воркера нет.
- **Переключение:** новый воркер готовится без расписания (код, вход Google, согласие скрипта, вход ChatGPT), пока старый работает. Затем старый гасится (расписание снято, сессия воркера отозвана, репозиторий или проект сохранены), и только после этого у нового включается расписание. Переключение отказывается, пока у старого воркера есть применение с неизвестным исходом: новый с чистым state мог бы потратить второй сброс. Новому воркеру переносятся только общие правила.
- **Пауза** снимает расписание и сохраняет сессию и state. Mac на паузе воркер не будит, а «Применить сейчас» и пробный запуск работают.
- Правило перед истечением: окно 8 ч на GitHub, 1 ч на Apps Script. Тик Apps Script `everyMinutes(5)` — ~5–10 из 90 минут суточной квоты триггеров, общей для всех скриптов пользователя.
- Внеочередная проверка с Mac (ADR-0005) работает на обеих площадках. На Apps Script Mac будит воркер через `doPost`.
- На Apps Script у каждого пользователя свой скрипт в его аккаунте. State лежит в Script Properties без шифрования: ключ лежал бы рядом. Повседневные действия (статус, журнал, правила, пауза, «Применить сейчас», пробный запуск, вход ChatGPT) идут в `doPost` web app (`ANYONE_ANONYMOUS`) с секретом из Keychain. `doPost` не возвращает токены. Токен Google нужен CLI только для деплоя: установки, `upgrade`, починки и переключения. `upgrade` обновляет только активный воркер.
- О потере сессии на Apps Script сообщает письмо Google о сбое триггера (тик бросает исключение) и сразу показывает `status`. Отдельного scope для `MailApp` нет.

**Уточняет** ADR-0004: GitHub больше не единственная площадка, и окно 8 ч относится только к нему. Уточняет ADR-0005: Mac будит активный воркер на любой площадке и не будит воркер на паузе.

**Отвергнуто.**
- Заменить GitHub на Apps Script. Не каждому подходит Google-аккаунт с двумя предупреждениями о непроверенном приложении.
- Один центральный скрипт в нашем верифицированном GCP-проекте (исследование `.scratch/apps-script-worker/research-setup-automation.md`). Он убрал бы переключатель, экран «небезопасно» и неудаляемый проект. Но код, который обрабатывает сессии ChatGPT всех пользователей, был бы нашим и обновлялся бы нами одновременно для всех: та же цепочка поставки, из-за которой ADR-0004 отверг reusable action.
- Сначала гасить старый воркер, потом поднимать новый. Сбой посередине оставлял пользователя без воркера, а вернуть старый стоило нового входа в ChatGPT.
- Шифровать state в Script Properties: ключ пришлось бы хранить там же.

**Последствия.**
- В тестовом режиме OAuth-клиента refresh token Google живёт 7 дней, поэтому вход Google просится почти при каждом `upgrade`, пока клиент не верифицирован (3–5 рабочих дней, нужны домен, privacy policy и видео).
- Экран «небезопасно» у скрипта в default GCP-проекте остаётся и после верификации CLI-клиента. Переключатель `usersettings` API не имеет: CLI открывает страницу и повторяет запрос.
- Удалить проект скрипта из CLI нельзя (scope `drive` restricted). `uninstall` снимает триггер, отзывает сессию и доступ скрипта, удаляет развёртывание, а проект пользователь удаляет сам. Вариант с bound-скриптом пустой таблицы ждёт пробы.
- Двойной тик в одну минуту (наблюдался в пробе) требует от тика на Apps Script `LockService` и идемпотентности.
