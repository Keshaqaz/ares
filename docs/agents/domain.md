# Доменные документы

## Перед изучением проекта

- Прочитайте корневой `CONTEXT.md`.
- Прочитайте ADR в `docs/adr/`, относящиеся к области предстоящей работы.
- Если документа или папки нет, продолжайте работу без замечаний об отсутствии. Навык `domain-modeling`, в том числе через `grill-with-docs` и `improve-codebase-architecture`, создаёт документы по мере согласования терминов и решений.

## Структура

Проект использует single-context:

- `CONTEXT.md` — единый словарь терминов проекта.
- `docs/adr/` — архитектурные решения проекта.

Существующий `CONTEXT.md` сохраняется. ADR создаются по мере появления согласованных решений.

## Использование словаря

В названиях задач, предложениях рефакторинга, гипотезах и именах тестов используйте термины в значениях из `CONTEXT.md`, учитывая указанные там нежелательные синонимы.

Если нужного понятия нет в словаре, проверьте, используется ли оно в проекте. Реальный пробел отметьте для `domain-modeling`.

## Конфликты с ADR

Если предложение противоречит существующему ADR, явно укажите номер решения, суть противоречия и причину, по которой предлагается пересмотр.
