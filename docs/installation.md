# Установка и использование

[English](installation.en.md) · **Русский**

## Что понадобится

- Mac на macOS. Сам воркер работает в облаке — на GitHub Actions или в Google Apps Script; Mac нужен для команд и, если хотите, для проверки недельного лимита (см. [Проверка с Mac](#проверка-с-mac)).
- Аккаунт GitHub или Google — в нём будет жить воркер. Бесплатного плана GitHub достаточно; для Google подходит любой аккаунт.
- Платная подписка ChatGPT, на которой выдаются сбросы лимита.

## Установка

```sh
brew install keshaqaz/tap/aures
```

Из исходников (нужен Node 26):

```sh
git clone https://github.com/Keshaqaz/aures.git && cd aures
npm ci && npm run build:worker
echo "alias aures='node $PWD/src/cli/main.ts'" >> ~/.zshrc && source ~/.zshrc
```

Последняя строка заводит команду `aures`, которой пользуется эта инструкция. Без неё пишите `node src/cli/main.ts` из папки проекта.

## Первая настройка

По умолчанию CLI говорит по-английски. Чтобы установка и всё остальное шли по-русски, сначала переключите язык:

```sh
aures language ru
aures setup
```

`setup` начинает с вопроса, где будет работать воркер:

```
Где будет работать воркер:
  1. GitHub Actions — запуск раз в час, но GitHub пропускает многие запуски; правило перед истечением начинает за 8 часов.
  2. Google Apps Script — запуск каждые 5 минут, правило перед истечением начинает за 1 час. При установке Google дважды предупредит о непроверенном приложении и нужно включить один переключатель; проект скрипта при удалении вы удаляете сами.
Введите 1 или 2: 
```

Обе площадки — облако в вашем аккаунте, без серверов и оплаты. Чем ещё они отличаются — в разделе [Сколько это стоит](#сколько-это-стоит). Выбор запоминается на этом Mac; команды работают с воркером одинаково, где бы он ни работал.

### Установка на GitHub

1. **Вход в GitHub.** CLI сам открывает страницу входа и копирует код в буфер обмена — вставьте его на странице и разрешите доступ. Если браузер не открылся, ссылка напечатана в терминале. Вход сохраняется в Связке ключей, повторно его не спросят.
2. **Репозиторий.** В вашем аккаунте появится приватный репозиторий `codex-auto-resets-worker`. В нём живёт воркер.
3. **Вход в ChatGPT.** CLI сам открывает страницу входа и копирует код в буфер — вставьте его и войдите в аккаунт со сбросами. Это отдельный вход только для воркера: Codex на компьютере продолжит работать как раньше.
4. **Правила.** Выберите, когда применять сбросы (см. ниже). Enter оставляет как есть.
5. **Вход в ChatGPT для этого Mac.** Только если включено правило «Когда кончится недельный лимит». CLI сам открывает страницу и копирует ещё один код — вставьте его и войдите в тот же аккаунт ChatGPT. CLI ставит агента launchd, который следит за недельным лимитом:

   ```
   Вход в ChatGPT для этого Mac: он замечает конец недельного лимита (Codex не затронут).
   Откройте https://auth.openai.com/codex/device и введите код ABCD-12345 (код скопирован)
   Если браузер не открылся: https://auth.openai.com/codex/device
   Внеочередная проверка с этого Mac включена.
   ```

6. **Проверка.** CLI делает пробный запуск воркера: тот читает квоты и сбросы и говорит, что сделали бы правила, но сброс не применяет. Итог:

   ```
   Воркер работает. Сбросов: 2, ближайший истекает 22 октября 2026 г. в 15:00 UTC. Сейчас применять нечего.
   ```

   Если правила велят применить сброс уже сейчас, вместо «применять нечего» будет «Сейчас правила применили бы сброс RES67F8 (перед истечением)». Применит его следующий плановый запуск.

Если `setup` прервался, просто запустите его снова: он продолжит с того места, где остановился, и ничего не потеряет.

### Установка на Google Apps Script

CLI ставит воркер прямо в ваш Google-аккаунт: в нём появится проект скрипта `aures-worker`. Каждую нужную страницу CLI открывает сам и сам продолжает, когда вы закончили, — копировать ничего не нужно. Перед началом он предупреждает о том, что покажет Google:

```
Google дважды покажет «Google не проверял это приложение»: при входе aures в Google и когда вы разрешите скрипту воркера работать. И приложение, и скрипт ваши, Google их просто не проверял.
Чтобы пройти, нажмите «Дополнительные настройки», затем «Перейти… (небезопасно)».
```

Вся установка на Google в терминале выглядит так:

<img src="assets/setup-ru.png" alt="aures setup в Google Apps Script: выбор площадки, вход в Google, переключатель API скрипта, правила, вход в ChatGPT и пробный запуск">

1. **Вход в Google.** CLI печатает «Вход в Google в браузере. На странице согласия отметьте все галочки или нажмите «Выбрать все».» и открывает страницу входа. Выберите аккаунт и пройдите первый экран «Google не проверял это приложение»: «Дополнительные настройки» → «Перейти… (небезопасно)». На странице согласия отметьте обе галочки — «проекты Google Apps Script» и «развёртывания проектов Google Apps Script» — или нажмите «Выбрать все». Браузер покажет «aures: вход в Google выполнен, вернитесь в терминал», и CLI продолжит сам. Если галочки не отмечены, CLI назовёт, какого доступа не хватает, и повторит вход.
2. **Переключатель API скрипта.** Пока API выключен, Google не даёт развернуть воркер. CLI печатает «Включите API скрипта Google Apps: https://script.google.com/home/usersettings», открывает эту страницу и объясняет: «На этой странице закройте приветствие, если оно появится, откройте строку «API скрипта приложений Google Apps» и нажмите переключатель. aures продолжит сам.» Переключатель нужен один раз; CLI проверяет его каждые 5 секунд и продолжит сам.
3. **Проект и web app.** В аккаунте появится проект `aures-worker`; CLI развернёт из него web app и напечатает «Воркер развёрнут: …». Адрес web app запоминается на этом Mac. Несколько секунд после развёртывания Google ещё отдаёт прежнюю версию web app; CLI пережидает это сам («Ждём, когда Google начнёт отдавать новую версию воркера…»), до минуты.
4. **Согласие скрипта.** CLI печатает «Разрешите скрипту воркера работать: …», открывает адрес web app и просит: «Выберите свой аккаунт, пройдите «Google не проверял это приложение» через «Дополнительные настройки» и нажмите «Разрешить». aures продолжит сам.» Это второй экран «непроверенное приложение». Выберите тот же аккаунт и разрешите — страница покажет «Готово, вернитесь в терминал», и CLI продолжит сам.
5. **Правила.** Те же два правила, что и на GitHub, только окно «перед истечением» — последний час: «1. Перед истечением (в последний час) — включено».
6. **Вход в ChatGPT.** Как на GitHub: CLI сам открывает страницу и копирует код в буфер — вставьте его и войдите в аккаунт со сбросами. Это отдельный вход только для воркера; Codex на компьютере продолжит работать как раньше.
7. **Расписание.** «Воркер запускается каждые 5 минут.»
8. **Проверка.** «Проверяем воркер…» — пробный запуск, как на GitHub: воркер читает квоты и сбросы и говорит, что сделали бы правила, но сброс не применяет.

Прерванный `setup` можно просто запустить снова: он продолжит в том же проекте и добавит только недостающее. Если вы удалили проект в Google, CLI создаст новый.

## Правила

| Правило | По умолчанию | Что делает |
| --- | --- | --- |
| Перед истечением (на GitHub — последние 8 часов, на Google — последний час) | включено | Применяет сброс, когда до его истечения остаётся меньше 8 часов на GitHub или меньше часа на Google. |
| Когда кончится недельный лимит | выключено | Как только воркер увидит, что недельный лимит кончился, применяет сброс с ближайшим сроком. На Google воркер сам замечает конец лимита каждые 5 минут, даже когда Mac выключен; на GitHub, пока Mac не спит, конец лимита замечает проверка с Mac, и сброс приходит через несколько минут. |

Правила действуют на все сбросы сразу и работают независимо друг от друга. Изменить их можно в любой момент на экране `aures` или командой `aures rules`. Новые правила заработают со следующего запуска воркера. На GitHub при включении недельного правила CLI попросит код ChatGPT для этого Mac, как в шаге 5 установки; при выключении он уберёт проверку с Mac, а вход Mac в ChatGPT оставит, чтобы при повторном включении код не понадобился. На Google проверка с Mac не ставится: воркер сам следит за лимитом.

На GitHub воркер запускается примерно раз в час, но GitHub иногда задерживает запуски на несколько часов. Поэтому срабатывание правил не привязано к точной минуте. На Google воркер запускается каждые 5 минут, и правила срабатывают точнее.

## Проверка с Mac

Проверка с Mac относится к воркеру на GitHub: агент ставится, когда воркер работает там. На Google она не нужна — воркер сам читает лимит каждые 5 минут, даже когда Mac выключен.

Смена площадки агента не трогает. Если воркер переехал с GitHub на Google, агент остаётся и, когда лимит кончится, будит воркер на Google по адресу web app с секретом из Связки ключей; вреда в этом нет, а убирает агента `aures uninstall`. Если воркер переехал с Google на GitHub при включённом недельном правиле, агента поставит `aures setup`.

Пока включено правило «Когда кончится недельный лимит» (на GitHub), агент launchd раз в 2 минуты запускает `aures watch`. Это короткий проход без окон и вопросов:

1. Читает недельный лимит своим входом Mac в ChatGPT. Это не тратит ни лимит, ни токены. Пока израсходовано меньше 80%, лимит читается раз в 10 минут, ближе к концу — на каждом проходе.
2. Если лимит кончился, запускает воркер через GitHub тем же входом в GitHub из Связки ключей, что и команды. Если через 15 минут лимит всё ещё кончен, запускает ещё раз, потом ещё через час: не больше трёх запусков на одно недельное окно. Повторно не запускает, если воркер не видит ни одного сброса.
3. Записывает итог одной строкой со временем в `~/Library/Logs/codex-auto-resets/watch.log`.

Сам Mac сброс не применяет. Воркер снова читает лимит своим входом и решает по правилам, поэтому ошибка на Mac сброс не тратит. Конец лимита виден, из какого бы клиента ни шла работа: Codex, opencode, телефон, другой компьютер.

Проверка работает, только пока Mac не спит и вы вошли в свою учётную запись macOS. В остальное время конец лимита заметит плановый запуск воркера.

Агент ничего не спрашивает и никуда не входит. Если вход Mac в ChatGPT потерян, проход пропускается, а `status` подсказывает, что делать. Если нет входа в GitHub, проход тоже пропускается; войти заново попросит любая команда.

Строки в `watch.log` (после времени прохода):

| Строка | Что значит |
| --- | --- |
| `paused` | Воркер на паузе: проход не читает лимит и никого не будит. |
| `switching` | Переключение площадки не завершено, активного воркера нет. |
| `idle` | Лимит не кончился, или воркер на это недельное окно уже запускали. |
| `quiet` | Проход не читал лимит: до конца лимита далеко, или все запуски на это окно уже сделаны. |
| `dispatched` | Лимит кончился, воркер запущен. |
| `dispatched (2 of 3)`, `dispatched (3 of 3)` | Лимит так и не обновился, воркер запущен повторно. |
| `no_resets` | Лимит так и не обновился, но сбросов нет; на это окно воркер больше не запускается. |
| `transient_error: …` | ChatGPT временно не ответил, следующий проход повторит. Если подряд идут `transient_error: wham_429`, ChatGPT ограничивает частоту опроса, и сброс придёт позже. |
| `reauth_required…` | Вход Mac в ChatGPT потерян. Запустите `aures setup`. |
| `no_session` | Входа Mac в ChatGPT нет. Если недельное правило включено, запустите `aures setup`. |
| `no_github_token`, `github_error: unauthorized` | Входа в GitHub нет в Связке ключей, он устарел или Связка ключей заблокирована. Любая команда, например `aures status`, попросит войти заново. |
| `no_worker`, `foreign_repository`, `dispatch_refused`, `github_error: …` | Репозитория воркера нет, он создан не CLI или открыт всем, workflow выключен или GitHub не ответил. Подробности покажет `aures status`. |
| `no_secret`, `no_access`, `forbidden`, `refused: …`, `google_error: …` | Только для воркера на Google: в Связке ключей нет секрета воркера, у скрипта нет доступа, секрет не подошёл, воркер отказал или Google не ответил. Окно не записывается, следующий проход повторит; подробности покажет `aures status`. |
| `error: …` | Непредвиденная ошибка прохода; следующий проход начнёт заново. |

Если в конце строки стоит `(watch.json not saved)`, проход не смог записать `watch.json`.

## Каждый день

Откройте экран:

```sh
aures
```

<img src="assets/status-ru.png" alt="Экран aures: сбросы сверху, правила снизу, воркер в Google Apps Script">

Сверху сбросы со сроками, снизу общие правила, под ними строка о воркере: когда он запускался и что применил последним. «Скоро применится» у сброса значит, что он в последних 8 часах на GitHub или в последнем часе на Google и правило «перед истечением» его применит.

- `↑` `↓` — выбрать сброс или правило.
- `Enter` на сбросе — применить его сейчас. Экран спросит подтверждение, `y` — да. CLI дождётся воркера и напишет итог; на GitHub это может занять несколько минут, на Google — секунды. Сброс одноразовый, отменить применение нельзя.
- `Enter` на правиле — включить или выключить его. На GitHub при включении недельного правила на экране появится код ChatGPT для этого Mac, как в шаге 5 установки.
- `Tab` — экран «Воркер»: площадка, аккаунты, действия и журнал запусков (см. ниже).
- `l` — переключить язык (EN · RU в шапке), выбор запоминается.
- `r` — обновить, `q` — выйти.

Если что-то не так, внизу будет строка с `!` и подсказкой, что делать. У недельного правила на GitHub видно, работает ли проверка с Mac: «проверка с Mac работает» или «не работает». Во втором случае агент не запущен или вход Mac в ChatGPT потерян, а строка с `!` скажет, что делать.

`aures status` печатает то же самое один раз, без управления. Команды `apply-now` и `rules` делают то же, что `Enter` на экране, через вопросы в терминале.

Если воркер работает на Google, экран и команды те же, а отличий немного:

- Строка о воркере показывает следующий запуск («воркер работает · следующий запуск ожидается через 3 мин»), внизу — ссылка на проект скрипта.
- Команды общаются с воркером напрямую по адресу web app с секретом из Связки ключей — вход Google для них не нужен.
- Если воркер потерял вход в ChatGPT, об этом скажет `aures status` («Воркер потерял вход в ChatGPT. Войдите заново: `aures login`.»), а Google вдобавок пришлёт письмо о сбое триггера.
- На новом Mac (или если файлы CLI удалены) любая команда спросит, где воркер: «Этот Mac не знает, где работает воркер» и «Где искать? Введите 1 или 2». Выберите Google, откройте проект `aures-worker` на script.google.com и вставьте ссылку из адресной строки.

### Экран «Воркер»

`Tab` на экране сбросов открывает экран «Воркер», ещё один `Tab` возвращает обратно. Шапка та же, под ней четыре блока; `↑` `↓` выбирают строку, `Enter` выполняет, а `l`, `r` и `q` работают как на экране сбросов.

<img src="assets/worker-ru.png" alt="Экран «Воркер»: площадка и её состояние, аккаунты, действия и живой журнал">

**«ВОРКЕР».** Площадка («GitHub Actions» или «Google Apps Script») и её состояние: «активен»; у воркера на паузе — жёлтое «на паузе», а пока переключение площадки не завершено — красное «активного воркера нет: переключение не завершено». Ниже — ссылка на репозиторий или проект скрипта.

**«АККАУНТЫ».** Две строки, у каждой справа действие «войти заново»:

- «GitHub» или «Google» — аккаунт площадки: логин GitHub или, на Google, адрес почты, если вход его сообщил; если аккаунт неизвестен, так и написано. «Войти заново» обновляет вход CLI в площадку; на GitHub это обязан быть аккаунт репозитория воркера, иначе aures вернёт прежний вход и попросит нужный.
- «ChatGPT» — аккаунт воркера и его состояние: «вход работает» или «вход потерян». «Войти заново» открывает воркеру новую сессию ChatGPT, как `aures login`.

**«ДЕЙСТВИЯ».** Курсор открывается на первом действии.

- «Проверить сейчас» — пробный запуск: воркер читает квоты и сбросы и говорит, что сделали бы правила, но сброс не применяет. На GitHub это запуск Actions, у действия пометка «~1 мин Actions».
- «Починить» — заново кладёт текущую версию воркера на площадку; когда курсор на действии, под ним подпись: «Заново залить текущую версию воркера и вернуть расписание на этой площадке. Сбросы, правила, вход в ChatGPT и журнал не трогаются. Поможет, если воркер перестал запускаться или его файлы меняли вручную». У воркера на паузе расписание не возвращает.
- «Пауза» или «Снять с паузы» — показывается то, что подходит к состоянию воркера (см. «Пауза» ниже).
- «Переключиться на …» — переносит воркера на другую площадку, GitHub Actions или Google Apps Script (раздел «Смена площадки» ниже); у воркера на паузе этого действия нет.

Пока переключение площадки не завершено, других действий нет — только «Повторить переключение».

**«ЖУРНАЛ».** Живой журнал воркера: до 12 записей, новые сверху. В каждой — когда воркер запустился, что его запустило («по расписанию», «с Mac», «пробный», «применить сейчас», «вход»), чем запуск кончился («применять нечего», «сброс применён», «исход применения ещё неизвестен», «временная ошибка», «потерян вход в ChatGPT», «данные не читаются (…)» и другие) и сколько он длился. Действия с этого экрана попадают в журнал строками «aures · …».

Пока экран открыт, aures опрашивает воркера: на Google каждые 30 секунд, на GitHub каждую минуту. Над журналом строка «опрошен 12:04:31, ответил за 2,1 с», а если ответа не было — «опрошен …, не ответил: …», и журнал держит прошлое чтение. `Tab` обратно и выход с экрана останавливают опрос.

### Пауза

«Пауза» снимает у воркера расписание, не трогая больше ничего: на GitHub выключается workflow, на Google снимается триггер. Сессия ChatGPT, состояние и правила остаются на площадке, поэтому «Снять с паузы» возвращает расписание тому же воркеру без нового входа в ChatGPT: «Воркер снят с паузы: расписание вернулось.»

На паузе плановых запусков нет, поэтому правила не работают и сбросы могут истечь. Экран сбросов показывает строку «воркер на паузе» с предупреждением «Воркер на паузе: сбросы не применяются и каждый сгорит в свой срок активации. «Применить сейчас» продолжает работать.» и помечает сбросы «сгорит». «Применить сейчас» и «Проверить сейчас» работают и на паузе: на GitHub aures включает workflow на один запуск и выключает его обратно, на Google запуск идёт и без расписания. Проверка с Mac воркера на паузе не будит. «Починить» зальёт новую версию, но расписание не вернёт — «Воркер на паузе, расписание осталось снятым».

Действия «Переключиться на …» у воркера на паузе нет: сначала снимите его с паузы.

### Смена площадки

На экране «Воркер» (`Tab`) действие «Переключиться на …» переносит воркер на другую площадку без переустановки. Каждый шаг пишется в журнал на экране:

1. Если у воркера есть применение сброса с неизвестным исходом, переключение откажется и объяснит почему: новый воркер с чистым состоянием мог бы потратить второй сброс. Дождитесь следующего запуска воркера.
2. Новый воркер готовится без расписания, пока старый работает: вход в GitHub или Google, код текущей версии, перенос общих правил и вход в ChatGPT для новой сессии воркера (страница откроется сама, код — в буфере и на экране).
3. Старый воркер гасится: его сессия ChatGPT отзывается, расписание снимается, а репозиторий или проект остаётся для обратного переключения. Прямо перед этим его состояние читается заново: если за время подготовки появилось применение с неизвестным исходом или на GitHub идёт запуск воркера, переключение отменяется, старый воркер остаётся активным, а переключить можно снова после его следующего запуска.
4. У нового воркера включается расписание, затем идёт пробный запуск.

`Esc` до шага 3 отменяет переключение, и старый воркер остаётся как был. Если переключение прервалось после начала шага 3, активного воркера нет: `aures status` скажет об этом, `aures apply-now` и Enter на сбросе откажут, а на экране «Воркер» будет одно действие — «Повторить переключение». Воркер на паузе не переключается: сначала снимите его с паузы.

## Если что-то сломалось

Когда запуск воркера заканчивается ошибкой, платформа присылает письмо: GitHub — об ошибке Actions, Google — о сбое триггера. Запустите `aures status`: в нём будет причина и что делать. Частые случаи:

| Сообщение | Что сделать |
| --- | --- |
| Воркер потерял вход в ChatGPT | `aures login` и войдите заново. Правила и история сохранятся. |
| Воркер выключен в GitHub | Откройте ссылку из сообщения и нажмите **Enable workflow**. |
| Воркер не запускался уже N ч | Откройте ссылку из сообщения и проверьте, что GitHub Actions работает. Обычно запуски возобновляются сами. |
| GitHub не запускал воркер по расписанию уже N ч | Запуски с Mac и «Применить сейчас» идут, а плановые нет. От них зависит правило перед истечением. Проверьте GitHub Actions по ссылке из сообщения. |
| Google не запускал воркер по расписанию уже N ч | То же на Google: проверьте выполнения скрипта по ссылке из сообщения. |
| У воркера нет расписания | Сбросы не применяются. Почините воркер: «Починить» на экране «Воркер» (`Tab` в `aures`) вернёт расписание. |
| Воркер на Google не отвечает (у скрипта нет доступа, web app удалён, секрет этого Mac не подходит) | `aures setup` заново зальёт воркер. |
| Web app воркера всё ещё отвечает прежней версией | Google не переключился на новую версию за минуту после развёртывания. Повторите ту же команду через несколько минут. |
| Данные воркера в проекте Google не читаются (…) | `aures status` покажет причину. Поможет переустановка: `aures uninstall`, затем `aures setup`. |
| Это другой аккаунт ChatGPT | Войдите в тот аккаунт, для которого ставили воркер. Сменить аккаунт можно только переустановкой: `uninstall`, затем `setup`. |
| Установка не завершена | `aures setup`. |
| Воркер устарел | `aures upgrade`. |
| Вход этого Mac в ChatGPT потерян | `aures setup` и введите код ChatGPT для этого Mac заново. |
| Внеочередная проверка с этого Mac не запущена | `aures setup`: он снова поставит агента. |

Если `setup`, `rules` или `upgrade` пишет «Внеочередная проверка с этого Mac не запустилась (launchctl …)», launchd не принял агента. Остальное команда доделала; повторите `aures setup`.

## Обновление

```sh
brew upgrade aures
aures upgrade
```

Из исходников, в папке проекта:

```sh
git pull && npm ci && npm run build:worker
aures upgrade
```

`aures upgrade` обновляет воркер в вашем репозитории. Без неё там продолжит работать прежняя версия. Правила, история и вход в ChatGPT сохраняются. Если недельное правило включено, `upgrade` вдобавок перезагружает агента проверки с Mac, когда его plist изменился.

Если воркер работает на Google, `aures upgrade` заливает новую версию в тот же проект и то же развёртывание, поэтому адрес web app не меняется; правила, состояние воркера и журнал запусков остаются. Как и при установке, первые секунды после развёртывания CLI ждёт, пока Google начнёт отдавать новую версию. Для обновления нужен вход Google из Связки ключей. Пока OAuth-клиент aures не верифицирован, вход Google живёт 7 дней, поэтому upgrade может снова открыть вход — пройдите его как при установке: отметьте все галочки, а на экране «Google не проверял это приложение» нажмите «Дополнительные настройки» → «Перейти… (небезопасно)». Сообщения «Воркер обновлён, но скрипту нужно снова разрешить работать» и «Проекта или развёртывания воркера в Google больше нет» означают одно и то же: запустите `aures setup` — он развернёт воркер заново.

При установке из исходников агент запускает тот `node` и тот `src/cli/main.ts`, из которых вы последний раз запускали `setup`, `rules` или `upgrade`. Если перенесёте папку или смените Node, запустите `setup` ещё раз.

При установке через Homebrew агент запускает программу через ссылку `$(brew --prefix)/opt/aures`, поэтому после `brew upgrade` он сразу работает в новой версии.

До версии 0.3.0 программа называлась `codex-auto-resets`. Чтобы перейти на новое имя, обновитесь один раз по полному имени, а затем запустите `aures upgrade`:

```sh
brew update
brew upgrade keshaqaz/tap/aures
aures upgrade
```

Homebrew сам перенесёт установку под новое имя. Короче не получится: `brew upgrade` без имени и `brew upgrade codex-auto-resets` Homebrew 7 пропускает или отклоняет, пока новое имя не отмечено как доверенное. `aures upgrade` обновит воркер и переведёт агента проверки с Mac на команду `aures`. Репозиторий `codex-auto-resets-worker`, вход в GitHub и файлы на Mac остаются со старыми именами, переустанавливать ничего не нужно.

## Удаление

```sh
aures uninstall
```

Затем удалите программу: `brew uninstall aures`. При установке из исходников удалите папку проекта и строку `alias aures=…` из `~/.zshrc`.

`uninstall` спросит подтверждение и уберёт воркер с той площадки, где он работает, а вместе с ним всё, что относится к нему на этом Mac.

**На GitHub** `uninstall` попросит ещё раз войти в GitHub: на удаление репозитория нужно отдельное разрешение, и CLI его не сохраняет. Затем он отзовёт вход воркера в ChatGPT и удалит репозиторий. Потом уберёт с Mac агента проверки, отзовёт вход Mac в ChatGPT, удалит его файлы и лог, а в конце удалит вход в GitHub из Связки ключей. Дойдите по ссылке на страницу GitHub и нажмите **Revoke**, чтобы закрыть доступ полностью.

**На Google** `uninstall` останавливает воркер — снимает расписание, отзывает его вход в ChatGPT и доступ самого скрипта, — удаляет web app, отзывает вход aures в Google и удаляет из Связки ключей вход в Google и секрет воркера. После этого от проекта ничего не исходит (проверено на аккаунте владельца 21 октября 2026 г.): запись скрипта сама пропадает со страницы «Сторонние приложения» (myaccount.google.com/connections), триггер, если он остался в списке проекта, больше не запускается, а web app без доступа скрипта отвечает только страницей входа. Сам проект скрипта CLI удалить не может: у Apps Script API нет такого вызова, а доступ Drive (drive.file) на отдельный проект скрипта не распространяется. Поэтому в конце печатаются ручные шаги:

```
Осталось сделать вручную:
  1. Удалите проект aures-worker на странице https://script.google.com/home/projects/…
  2. Если на странице https://myaccount.google.com/connections осталась запись aures-worker, удалите у неё доступ.
```

Проект перенесите в корзину на script.google.com сами — или оставьте: без расписания, входа и доступов он ничего не делает.

Если программу уже удалили, а агент остался, лучше поставить её снова и выполнить `uninstall`: только он отзывает вход Mac в ChatGPT. Убрать агента и файлы вручную, без отзыва входа:

```sh
launchctl bootout gui/$(id -u)/com.github.keshaqaz.codex-auto-resets.watch
rm ~/Library/LaunchAgents/com.github.keshaqaz.codex-auto-resets.watch.plist
rm -r ~/Library/Application\ Support/codex-auto-resets ~/Library/Logs/codex-auto-resets
```

## Что где хранится

| Где | Что |
| --- | --- |
| Связка ключей на Mac | вход в GitHub; если воркер на Google — ещё вход в Google и секрет web app (записи службы `codex-auto-resets`: `github`, `google`, `worker-secret`) |
| Репозиторий `codex-auto-resets-worker` (GitHub) | код воркера, расписание, правила, открытая сводка (сбросы и их сроки, без входа и данных аккаунта) и зашифрованный вход воркера в ChatGPT |
| Секрет `STATE_KEY` в настройках репозитория | ключ, которым зашифрован вход воркера (GitHub) |
| Проект скрипта `aures-worker` (Google) | код воркера, расписание, вход воркера в ChatGPT, правила и журнал последних 30 запусков — всё в свойствах проекта (Script Properties) |
| `~/Library/Application Support/codex-auto-resets/install.json` | площадка воркера, на Google — ещё проект и адрес его web app; адреса почты аккаунтов Google и ChatGPT для экрана «Воркер», пометка паузы и незавершённого переключения площадки |
| `~/Library/LaunchAgents/com.github.keshaqaz.codex-auto-resets.watch.plist` | агент проверки с Mac, пока включено недельное правило |
| `~/Library/Application Support/codex-auto-resets/chatgpt-session.json` | вход этого Mac в ChatGPT, пока включено недельное правило |
| `~/Library/Application Support/codex-auto-resets/watch.json` | недельное окно, на которое уже запускали воркер, и итог последней проверки |
| `~/Library/Logs/codex-auto-resets/watch.log` | строка на каждую проверку с Mac, 20–35 КБ в сутки, без ротации |

Вход в GitHub даёт CLI доступ ко всем вашим репозиториям, как у `gh`. Репозиторий воркера должен оставаться приватным: если сделать его публичным, CLI откажется с ним работать.

На Google вход воркера в ChatGPT лежит в Script Properties без шифрования: ключ пришлось бы хранить там же ([ADR-0007](adr/0007-two-worker-platforms.md)). Web app воркера открыт по своему адресу, но отвечает только на запросы с секретом из Связки ключей вашего Mac и не возвращает токены. Вход в Google нужен CLI только чтобы развернуть воркер или обновить его.

Вход Mac в ChatGPT хранится не в Связке ключей, а в файле с правами `0600`: он длиннее, чем CLI может безопасно передать в Связку ключей (подробности в [ADR-0005](adr/0005-weekly-check-from-mac.md)). Файл может прочитать любая программа, запущенная от вашего пользователя macOS. Это тот же уровень доступа, что у входа Codex. Вход нужен только для чтения лимита, а отзывает его `uninstall`.

## Сколько это стоит

Ничего — на любой площадке.

**GitHub.** Каждый запуск воркера засчитывается GitHub Actions как минимум за минуту, в месяц выходит до ~750 минут. Проверка с Mac добавляет не больше одного запуска на недельное окно. На бесплатном плане GitHub даёт 2000 минут в месяц на приватные репозитории. Если в других ваших приватных репозиториях тоже работают Actions, учитывайте общий расход.

**Google.** Воркер работает на триггерах Apps Script. У Google 90 минут общего времени триггеров в сутки на все скрипты аккаунта; воркер aures занимает примерно 5–10 минут. Если в Apps Script работают и другие ваши скрипты, учитывайте общий расход.

Деньги — не единственная цена. У GitHub это задержки плановых запусков, иногда по нескольку часов, поэтому окно правила «перед истечением» — 8 часов. У Google — два экрана «Google не проверял это приложение», переключатель API при установке и проект скрипта, который при удалении приходится удалять вручную.
