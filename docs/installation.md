# Установка и использование

[English](installation.en.md) · **Русский**

## Что понадобится

- Mac на macOS. Сам воркер работает в GitHub, Mac нужен для команд и, если хотите, для проверки недельного лимита (см. [Проверка с Mac](#проверка-с-mac)).
- Аккаунт GitHub. Хватит бесплатного.
- Платная подписка ChatGPT, на которой выдаются сбросы лимита.

## Установка

```sh
brew install keshaqaz/tap/codex-auto-resets
```

Из исходников (нужен Node 26):

```sh
git clone https://github.com/Keshaqaz/ares.git && cd ares
npm ci && npm run build:worker
echo "alias codex-auto-resets='node $PWD/src/cli/main.mjs'" >> ~/.zshrc && source ~/.zshrc
```

Последняя строка заводит команду `codex-auto-resets`, которой пользуется эта инструкция. Без неё пишите `node src/cli/main.mjs` из папки проекта.

## Первая настройка

По умолчанию CLI говорит по-английски. Чтобы установка и всё остальное шли по-русски, сначала переключите язык:

```sh
codex-auto-resets language ru
codex-auto-resets setup
```

<img src="assets/setup-ru.png" alt="codex-auto-resets setup: вход в GitHub и ChatGPT, правила, проверка с Mac и пробный запуск">

1. **Вход в GitHub.** Откройте ссылку, введите код и разрешите доступ. Вход сохраняется в Связке ключей, повторно его не спросят.
2. **Репозиторий.** В вашем аккаунте появится приватный репозиторий `codex-auto-resets-worker`. В нём живёт воркер.
3. **Вход в ChatGPT.** Откройте ссылку, введите код и войдите в аккаунт со сбросами. Это отдельный вход только для воркера: Codex на компьютере продолжит работать как раньше.
4. **Правила.** Выберите, когда применять сбросы (см. ниже). Enter оставляет как есть.
5. **Вход в ChatGPT для этого Mac.** Только если включено правило «Когда кончится недельный лимит». Откройте ссылку и введите ещё один код, в тот же аккаунт ChatGPT. CLI ставит агента launchd, который следит за недельным лимитом:

   ```
   Вход в ChatGPT для этого Mac: он замечает конец недельного лимита (Codex не затронут).
   Откройте https://auth.openai.com/codex/device и введите код ABCD-12345
   Внеочередная проверка с этого Mac включена.
   ```

6. **Проверка.** CLI один раз запускает воркер и показывает итог:

   ```
   Воркер работает. Сбросов: 2, ближайший истекает 22 октября 2026 г. в 15:00 UTC.
   ```

Если `setup` прервался, просто запустите его снова: он продолжит с того места, где остановился, и ничего не потеряет.

## Правила

| Правило | По умолчанию | Что делает |
| --- | --- | --- |
| Перед истечением (в последние 8 часов) | включено | Применяет сброс, когда до его истечения остаётся меньше 8 часов. |
| Когда кончится недельный лимит | выключено | Как только воркер увидит, что недельный лимит кончился, применяет сброс с ближайшим сроком. Пока Mac не спит, конец лимита замечает проверка с Mac, и сброс приходит через несколько минут. |

Правила действуют на все сбросы сразу и работают независимо друг от друга. Изменить их можно в любой момент на экране `codex-auto-resets` или командой `codex-auto-resets rules`. Новые правила заработают со следующего запуска воркера. Если включить недельное правило, CLI попросит код ChatGPT для этого Mac, как в шаге 5 установки. Если выключить, он уберёт проверку с Mac и отзовёт вход Mac в ChatGPT.

Воркер запускается примерно раз в час, но GitHub иногда задерживает запуски на несколько часов. Поэтому срабатывание правил не привязано к точной минуте.

## Проверка с Mac

Пока включено правило «Когда кончится недельный лимит», агент launchd раз в 2 минуты запускает `codex-auto-resets watch`. Это короткий проход без окон и вопросов:

1. Читает недельный лимит своим входом Mac в ChatGPT. Это не тратит ни лимит, ни токены.
2. Если лимит кончился, один раз на это недельное окно запускает воркер через GitHub, тем же входом в GitHub из Связки ключей, что и команды.
3. Записывает итог одной строкой со временем в `~/Library/Logs/codex-auto-resets/watch.log`.

Сам Mac сброс не применяет. Воркер снова читает лимит своим входом и решает по правилам, поэтому ошибка на Mac сброс не тратит. Конец лимита виден, из какого бы клиента ни шла работа: Codex, opencode, телефон, другой компьютер.

Проверка работает, только пока Mac не спит и вы вошли в свою учётную запись macOS. В остальное время конец лимита заметит плановый запуск воркера.

Агент ничего не спрашивает и никуда не входит. Если вход Mac в ChatGPT потерян, проход пропускается, а `status` подсказывает, что делать. Если нет входа в GitHub, проход тоже пропускается; войти заново попросит любая команда.

Строки в `watch.log` (после времени прохода):

| Строка | Что значит |
| --- | --- |
| `idle` | Лимит не кончился, или воркер на это недельное окно уже запускали. |
| `dispatched` | Лимит кончился, воркер запущен. |
| `transient_error: …` | ChatGPT временно не ответил, следующий проход повторит. Если подряд идут `transient_error: wham_429`, ChatGPT ограничивает частоту опроса, и сброс придёт позже. |
| `reauth_required…` | Вход Mac в ChatGPT потерян. Запустите `codex-auto-resets setup`. |
| `no_session` | Входа Mac в ChatGPT нет. Если недельное правило включено, запустите `codex-auto-resets setup`. |
| `no_github_token`, `github_error: unauthorized` | Входа в GitHub нет в Связке ключей, он устарел или Связка ключей заблокирована. Любая команда, например `codex-auto-resets status`, попросит войти заново. |
| `no_worker`, `foreign_repository`, `dispatch_refused`, `github_error: …` | Репозитория воркера нет, он создан не CLI или открыт всем, workflow выключен или GitHub не ответил. Подробности покажет `codex-auto-resets status`. |
| `error: …` | Непредвиденная ошибка прохода; следующий проход начнёт заново. |

Если в конце строки стоит `(watch.json not saved)`, проход не смог записать `watch.json`.

## Каждый день

Откройте экран:

```sh
codex-auto-resets
```

<img src="assets/status-ru.png" alt="Экран codex-auto-resets: сбросы сверху, правила снизу">

Сверху сбросы со сроками, снизу общие правила, под ними строка о воркере: когда он запускался и что применил последним. «Скоро применится» у сброса значит, что он в последних 8 часах и правило «перед истечением» его применит.

- `↑` `↓` — выбрать сброс или правило.
- `Enter` на сбросе — применить его сейчас. Экран спросит подтверждение, `y` — да. CLI дождётся воркера и напишет итог; это может занять несколько минут. Сброс одноразовый, отменить применение нельзя.
- `Enter` на правиле — включить или выключить его. При включении недельного правила на экране появится код ChatGPT для этого Mac, как в шаге 5 установки.
- `l` — переключить язык (EN · RU в шапке), выбор запоминается.
- `r` — обновить, `q` — выйти.

Если что-то не так, внизу будет строка с `!` и подсказкой, что делать. У недельного правила видно, работает ли проверка с Mac: «проверка с Mac работает» или «не работает». Во втором случае агент не запущен или вход Mac в ChatGPT потерян, а строка с `!` скажет, что делать.

`codex-auto-resets status` печатает то же самое один раз, без управления. Команды `apply-now` и `rules` делают то же, что `Enter` на экране, через вопросы в терминале.

## Если что-то сломалось

Когда запуск воркера заканчивается ошибкой, GitHub присылает письмо. Запустите `codex-auto-resets status`: в нём будет причина и что делать. Частые случаи:

| Сообщение | Что сделать |
| --- | --- |
| Воркер потерял вход в ChatGPT | `codex-auto-resets login` и войдите заново. Правила и история сохранятся. |
| Воркер выключен в GitHub | Откройте ссылку из сообщения и нажмите **Enable workflow**. |
| Воркер не запускался уже N ч | Откройте ссылку из сообщения и проверьте, что GitHub Actions работает. Обычно запуски возобновляются сами. |
| Это другой аккаунт ChatGPT | Войдите в тот аккаунт, для которого ставили воркер. Сменить аккаунт можно только переустановкой: `uninstall`, затем `setup`. |
| Установка не завершена | `codex-auto-resets setup`. |
| Воркер устарел | `codex-auto-resets upgrade`. |
| Вход этого Mac в ChatGPT потерян | `codex-auto-resets setup` и введите код ChatGPT для этого Mac заново. |
| Внеочередная проверка с этого Mac не запущена | `codex-auto-resets setup`: он снова поставит агента. |

Если `setup`, `rules` или `upgrade` пишет «Внеочередная проверка с этого Mac не запустилась (launchctl …)», launchd не принял агента. Остальное команда доделала; повторите `codex-auto-resets setup`.

## Обновление

```sh
brew upgrade codex-auto-resets
codex-auto-resets upgrade
```

Из исходников, в папке проекта:

```sh
git pull && npm ci && npm run build:worker
codex-auto-resets upgrade
```

`codex-auto-resets upgrade` обновляет воркер в вашем репозитории. Без неё там продолжит работать прежняя версия. Правила, история и вход в ChatGPT сохраняются. Если недельное правило включено, `upgrade` вдобавок перезагружает агента проверки с Mac, когда его plist изменился.

При установке из исходников агент запускает тот `node` и тот `src/cli/main.mjs`, из которых вы последний раз запускали `setup`, `rules` или `upgrade`. Если перенесёте папку или смените Node, запустите `setup` ещё раз.

При установке через Homebrew агент запускает программу через ссылку `$(brew --prefix)/opt/codex-auto-resets`, поэтому после `brew upgrade` он сразу работает в новой версии.

## Удаление

```sh
codex-auto-resets uninstall
```

Затем удалите программу: `brew uninstall codex-auto-resets`. При установке из исходников удалите папку проекта и строку `alias codex-auto-resets=…` из `~/.zshrc`.

`uninstall` попросит ещё раз войти в GitHub: на удаление репозитория нужно отдельное разрешение, и CLI его не сохраняет. Затем он отзовёт вход воркера в ChatGPT и удалит репозиторий. Потом уберёт с Mac агента проверки, отзовёт вход Mac в ChatGPT, удалит его файлы и лог, а в конце удалит вход в GitHub из Связки ключей. Дойдите по ссылке на страницу GitHub и нажмите **Revoke**, чтобы закрыть доступ полностью.

Если программу уже удалили, а агент остался, лучше поставить её снова и выполнить `uninstall`: только он отзывает вход Mac в ChatGPT. Убрать агента и файлы вручную, без отзыва входа:

```sh
launchctl bootout gui/$(id -u)/com.github.keshaqaz.codex-auto-resets.watch
rm ~/Library/LaunchAgents/com.github.keshaqaz.codex-auto-resets.watch.plist
rm -r ~/Library/Application\ Support/codex-auto-resets ~/Library/Logs/codex-auto-resets
```

## Что где хранится

| Где | Что |
| --- | --- |
| Связка ключей на Mac | вход в GitHub (запись `codex-auto-resets`) |
| Репозиторий `codex-auto-resets-worker` | код воркера, расписание, правила, открытая сводка (сбросы и их сроки, без входа и данных аккаунта) и зашифрованный вход воркера в ChatGPT |
| Секрет `STATE_KEY` в настройках репозитория | ключ, которым зашифрован вход воркера |
| `~/Library/LaunchAgents/com.github.keshaqaz.codex-auto-resets.watch.plist` | агент проверки с Mac, пока включено недельное правило |
| `~/Library/Application Support/codex-auto-resets/chatgpt-session.json` | вход этого Mac в ChatGPT, пока включено недельное правило |
| `~/Library/Application Support/codex-auto-resets/watch.json` | недельное окно, на которое уже запускали воркер, и итог последней проверки |
| `~/Library/Logs/codex-auto-resets/watch.log` | строка на каждую проверку с Mac, 20–35 КБ в сутки, без ротации |

Вход в GitHub даёт CLI доступ ко всем вашим репозиториям, как у `gh`. Репозиторий воркера должен оставаться приватным: если сделать его публичным, CLI откажется с ним работать.

Вход Mac в ChatGPT хранится не в Связке ключей, а в файле с правами `0600`: он длиннее, чем CLI может безопасно передать в Связку ключей (подробности в [ADR-0005](adr/0005-weekly-check-from-mac.md)). Файл может прочитать любая программа, запущенная от вашего пользователя macOS. Это тот же уровень доступа, что у входа Codex. Вход нужен только для чтения лимита, а выключение недельного правила и `uninstall` его отзывают.

## Сколько это стоит

Ничего. Каждый запуск воркера засчитывается GitHub Actions как минимум за минуту, в месяц выходит до ~750 минут. Проверка с Mac добавляет не больше одного запуска на недельное окно. На бесплатном плане GitHub даёт 2000 минут в месяц на приватные репозитории. Если в других ваших приватных репозиториях тоже работают Actions, учитывайте общий расход.
